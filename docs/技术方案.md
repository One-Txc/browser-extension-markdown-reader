# MD 文档浏览插件 —— 技术方案

> 目标：在 Google Chrome 中打开本地 `file:///.../*.md` 文件时，自动以渲染后的 HTML 呈现。
> 版本：v2（Manifest V3）
>
> **v2 修订说明**：v1 误判「Chrome 打开 `.md` 会触发下载」，据此设计了「拦截导航 + 跳转扩展 viewer」的重型架构。
> 实测（`file:///D:/workspace/.../VoC%20Data%20Model.md` 可正常显示内容）证明 Chrome 对 `file://` 下的 `.md` 会渲染为**纯文本**。
> 因此主路径改为 **content script 就地替换**，架构从 3 层拦截降为 1 层注入，权限从 5 项降为 1 项。

## 零、M0 实测结论（2026-10-09，已确认）

样本：`file:///D:/workspace/vf-project/voc/voc-backend/.tmp/docs/VoC%20Data%20Model.md`

| 探测项 | 实测值 | 对实现的影响 |
|---|---|---|
| `document.contentType` | **`text/markdown`** | 页面判定条件确定，同时兼容 `text/plain` |
| `body` 子元素 | **1 个：`<pre>`**，`textContent` 14690 字符、167 行 | 取原文直接读 `body > pre`，零延迟零额外权限 |
| `pre` 内联样式 | `word-wrap: break-word; white-space: pre-wrap` | 替换 body 后这些样式消失，代码块样式需自行定义 |
| `document.title` | **空字符串** | 需自行从文件名设置标题（原以为 Chrome 会设） |
| `documentElement.textContent` | 与 `body.textContent` **等长**（14690） | 不会夹带 `<title>` 文本，但实现仍优先用 `body > pre` |
| 替换字符数 | **0**（UTF-8 解码干净） | 该文件为 UTF-8 |
| GBK 解码同一文件 | 出现替换字符 | 反向验证「两种解码比坏字符数」的嗅探策略有效 |
| SW `fetch(file://)` | **200 / 14893 bytes / 26ms** | 编码兜底与 DOM 读取失败的回退路径可用 |
| 相对路径解析 | `./img/a.png` → 同目录 `file://…/docs/img/a.png` | 确认无需重写 |
| 其它 md 扩展冲突 | `style[id]`、`script[src]`、dataset 标记全空 | 环境干净，但仍需幂等标记 |

### ⚠️ 意外发现：`chrome.extension.isAllowedFileSchemeAccess` 在 content script 中不存在

探针调用时抛出 `TypeError: chrome.extension.isAllowedFileSchemeAccess is not a function`。该 API 只暴露给扩展页面（popup / options）。

**这直接改变了权限检测的设计**。原方案打算在 content script 与 popup 两处都做自检，现在改为：

```
content script 注入成功 → 向 SW 发 hello → SW 落盘 storage: fileAccessProven = true
popup 读该标志 → 显示权限状态 / 展示引导
```

逻辑上更干净：**content script 能注入进来，本身就是权限已开的证明**，不需要再去问一个可能不存在的 API。

### M1 落地时额外修掉的两个坑

1. **中文锚点 id 被 `encodeURIComponent` 编码** —— markdown-it-anchor 的 `slugify` 若做 URL 编码，`# 标题一` 会变成 `id="%E6%A0%87%E9%A2%98%E4%B8%80"`，导致 Markdown 里手写的 `[跳转](#标题一)` 全部失效。改为保留 Unicode 字母、仅小写化并去标点（对齐 GitHub）。
2. **任务列表复选框可点击但改不了文件** —— `markdown-it-task-lists` 的 `enabled: true` 会渲染可交互复选框，用户勾选后刷新即丢，属于误导。改为 `enabled: false`（渲染为 `disabled`）。

两者的验证已固化为 `scripts/test-render.mjs` 的自动化断言（18 项）。

## 一、技术前提（实测确认）

### 前提 1：Chrome 会把 `file:///*.md` 渲染成纯文本页面 ✅

页面已存在 → content script 有注入机会 → **可以就地替换 DOM**。这是本方案的地基。

> 注意这是**环境相关**行为：Chrome 对 `file://` 的 MIME 推断会参考扩展名映射（Windows 上含注册表 `HKEY_CLASSES_ROOT\.md` 的 `Content Type`）。在装了 VS Code / Typora 等会改写文件关联的机器上，存在被判定为 `application/octet-stream` 而转为下载的可能。方案对此保留一层**可选兜底**（见 4.4）。

### 前提 2：必须用户手动开启「允许访问文件网址」⚠️

即使 manifest 声明了 `host_permissions: ["file:///*"]`，Chrome 仍要求在
`chrome://extensions` → 扩展详情页 → 打开 **「允许访问文件网址」（Allow access to file URLs）**。

- 检测：`chrome.extension.isAllowedFileSchemeAccess(callback)`（MV3 仍可用）
- 未开启时：content script **不会注入到 file:// 页面**，`fetch` 也无法读文件
- **这是本插件唯一的硬约束，也是唯一必须做的用户引导。** 不做引导页，用户会直接判定"插件没用"，这是这类扩展差评的头号来源。

### 前提 3：file:// 页面的 content script 无法自己 fetch 本地文件

MV3 里 content script 的 `fetch` 受**页面 CORS 约束**（跨源能力已在 MV3 中移除）。`file://` 页面 fetch `file://` 资源会被直接拒绝。

→ **读原文首选「从 DOM 直接取」，兜底走 Service Worker 代为 fetch。**（见 4.3）

## 二、总体架构

```
用户在地址栏打开 file:///D:/docs/a.md
        │
        ▼
Chrome 内置文本查看器渲染为纯文本（DOM 里是一个 <pre>）
        │
        ▼
content script  (matches: file:///*,  run_at: document_start)
   ├── 1. 判定是否 Markdown 页面（URL 后缀 + document.contentType）
   ├── 2. 【防闪烁】先隐藏 documentElement
   ├── 3. 【取原文】优先读 DOM 里的 <pre>.textContent
   │        └─ 失败 → sendMessage 给 SW → SW fetch(file://) → 回传文本
   │           （SW 路径还顺带解决 GBK 等非 UTF-8 编码）
   ├── 4. markdown-it 解析 → DOMPurify 消毒
   ├── 5. 替换 body，注入内联 CSS + 代码高亮 + TOC
   └── 6. finally 恢复可见（绝不允许因异常把页面留成白屏）
        │
        ▼
   URL 不变、相对路径不变、锚点不变 —— 图片和 md 互链全部天然可用
```

### 相比 v1 的收益（都是"白拿"的）

| 收益 | 原因 |
|---|---|
| **相对路径图片直接可用** | 页面 URL 仍是 `file:///D:/docs/a.md`，`![](./img/a.png)` 由浏览器按原目录解析，无需任何重写 |
| **md 互链天然可用** | 点 `<a href="./b.md">` → 浏览器导航到 `file:///.../b.md` → content script 再次接管，零额外代码 |
| **锚点跳转天然可用** | URL 不变，`#section` 直接生效 |
| **权限警告几乎为零** | 不再需要 `downloads` / `tabs` / `webNavigation`，商店审核阻力大降 |
| **Ctrl+F / 打印 / 复制** | 替换后是真实 DOM，浏览器原生能力全部正常 |
| **无导航劫持、无死循环风险** | 不碰 `tabs.update`，不产生第二个 URL |

## 四、模块设计

### 4.1 manifest.json

```json
{
  "manifest_version": 3,
  "name": "MD Reader - 本地 Markdown 阅读器",
  "version": "0.1.0",
  "description": "直接在 Chrome 中优雅地阅读本地 .md 文件",

  "permissions": ["storage"],
  "host_permissions": ["file:///*"],

  "background": {
    "service_worker": "src/background.js",
    "type": "module"
  },

  "content_scripts": [
    {
      "matches": ["file:///*"],
      "js": ["src/content.js"],
      "run_at": "document_start",
      "all_frames": false
    }
  ],

  "action": {
    "default_popup": "src/popup/popup.html",
    "default_title": "MD Reader"
  }
}
```

**权限对比**

| | v1 方案 | v2 方案 |
|---|---|---|
| permissions | downloads, tabs, webNavigation, storage, contextMenus | **storage** |
| host_permissions | file:///* | file:///* |
| 用户可见警告 | 「管理你的下载内容」「读取浏览记录」「读取和更改本机文件」 | **仅「读取和更改您在本机上的文件」** |

> `host_permissions: ["file:///*"]` 是必需的：它既是 content script 匹配的前提，也是 SW 兜底 `fetch(file://)` 的授权来源。

### 4.2 content.ts —— 主流程

```ts
// src/content.ts
import { renderMarkdown } from './render/markdown';
import { injectStyles } from './render/styles';
import { buildToc, setupTocSync } from './render/toc';
import { MD_RE } from './shared/const';

const THEME_STYLE_ID = '__md_reader_theme__';

(async function main() {
  // ---------- 1. 页面判定 ----------
  if (!MD_RE.test(location.pathname)) return;
  // Chrome 通常是 text/plain；某些版本/平台可能是 text/markdown，两者都接受
  const ct = document.contentType;
  if (ct !== 'text/plain' && ct !== 'text/markdown') return;

  // ---------- 2. 权限自检 ----------
  const allowed = await new Promise<boolean>((r) =>
    chrome.extension.isAllowedFileSchemeAccess(r)
  );
  if (!allowed) {
    // 注：未开权限时脚本根本不会注入，这里实际到不了；
    // 保留是为了 SW 兜底 fetch 失败时的一致性判断
    return;
  }

  // ---------- 3. 防闪烁 ----------
  // document_start 时 documentElement 通常已存在；不存在则退化为不隐藏（宁可不隐藏，也不要白屏）
  const root = document.documentElement;
  const prevVisibility = root?.style.visibility ?? '';
  if (root) root.style.visibility = 'hidden';

  try {
    // ---------- 4. 等原始文本就绪 ----------
    const raw = await readRawText();
    if (!raw || raw.trim() === '') return;   // 读不到就原样保留，什么都不做

    // ---------- 5. 渲染 ----------
    const html = renderMarkdown(raw, location.href);
    const main = document.createElement('main');
    main.className = 'markdown-body md-reader-root';
    main.innerHTML = html;

    // ---------- 6. 替换 ----------
    document.body.replaceChildren(main);
    document.body.classList.add('md-reader-body');
    injectStyles(document);
    buildToc(main);
    setupTocSync(main);

    // 记忆滚动位置（同目录 md 互链来回切换时不至于丢位置）
    const saved = sessionStorage.getItem('md-reader-scroll:' + location.href);
    if (saved) window.scrollTo(0, Number(saved));
    window.addEventListener('beforeunload', () => {
      sessionStorage.setItem('md-reader-scroll:' + location.href, String(window.scrollY));
    });
  } catch (e) {
    console.error('[MD Reader] 渲染失败，回退为原始文本', e);
  } finally {
    // ---------- 7. 无论如何恢复可见 ----------
    if (root) root.style.visibility = prevVisibility;
  }
})();

/**
 * 读取 Markdown 原文
 * 策略 A：直接读 Chrome 文本查看器的 DOM（零延迟、零额外权限）
 * 策略 B：交给 SW fetch（可处理编码、应对 DOM 结构变化）
 */
async function readRawText(): Promise<string> {
  await domReady();

  const fromDom = readFromDom();
  // 简单启发式：拿到了非空文本就认为成功
  if (fromDom && fromDom.trim().length > 0) return fromDom;

  try {
    const res = await chrome.runtime.sendMessage({ type: 'read-file', url: location.href });
    if (res?.ok) return res.text as string;
  } catch (e) {
    console.warn('[MD Reader] SW 兜底读取失败', e);
  }
  return '';
}

/** 从 DOM 提取纯文本原文 */
function readFromDom(): string | null {
  // Chrome 文本查看器：<body><pre>原文</pre></body>
  const pre = document.querySelector('body > pre');
  if (pre && pre.textContent != null) return pre.textContent;

  // 结构变化时的退化路径：body 直接就是文本节点集合
  if (document.body) {
    const t = document.body.textContent;
    if (t && t.trim()) return t;
  }
  return null;
}

function domReady(): Promise<void> {
  if (document.readyState !== 'loading') return Promise.resolve();
  return new Promise((r) =>
    document.addEventListener('DOMContentLoaded', () => r(), { once: true })
  );
}
```

**两个必须小心的点**

1. **绝不能用 `document.write`**。它会清空文档、丢掉 URL 语义，且在某些时序下直接白屏。用 `document.body.replaceChildren()`。
2. **隐藏与恢复必须成对**。用 `try/finally`，任何异常路径都要恢复 `visibility`，否则用户看到的是一张白纸 —— 这比不渲染严重得多。

### 4.3 background.ts —— 兜底读文件 + 设置

```ts
// src/background.ts

/** 兜底：由 SW 代读本地文件（content script 受 CORS 限制读不了 file://） */
chrome.runtime.onMessage.addListener((msg, _sender, sendResponse) => {
  if (msg?.type !== 'read-file') return;

  (async () => {
    try {
      const res = await fetch(msg.url, { cache: 'no-store' });
      const buf = await res.arrayBuffer();
      sendResponse({ ok: true, text: decode(buf), encoding: lastEncoding });
    } catch (e) {
      sendResponse({ ok: false, error: String(e) });
    }
  })();

  return true; // 异步响应
});

let lastEncoding = 'utf-8';

/**
 * 编码解码：中文用户的 .md 有相当比例是 GBK/GB18030
 * 先用 UTF-8 严格模式解，遇到替换字符则回退 GBK
 */
function decode(buf: ArrayBuffer): string {
  const utf8 = new TextDecoder('utf-8', { fatal: false }).decode(buf);
  // U+FFFD 比例过高 → 判定不是 UTF-8
  const bad = (utf8.match(/\uFFFD/g) ?? []).length;
  if (bad > 0 && bad / Math.max(1, utf8.length) > 0.001) {
    try {
      const gbk = new TextDecoder('gbk').decode(buf);
      if (!gbk.includes('\uFFFD')) {
        lastEncoding = 'gbk';
        return gbk;
      }
    } catch { /* 某些环境不支持 gbk，忽略 */ }
  }
  lastEncoding = 'utf-8';
  return utf8;
}
```

> SW 冷启动：MV3 的 Service Worker 会被消息唤醒，冷启动约 50–200 ms。只在 DOM 读取失败时才走这条路，正常情况不承担这个延迟。

### 4.4 可选兜底：downloads 拦截层

**默认不启用**，作为设置项供"在会触发下载的环境里"的用户打开。

保留这个开关的理由：`file://` 的 MIME 推断是环境相关的。用户 A 机器上能显示（已实测），用户 B 装了 VS Code 改了注册表关联就可能变下载。届时 content script 完全没有注入机会，只有 downloads 层能救。

启用后需额外声明 `"permissions": ["downloads", "tabs"]`，并增加：

```ts
// 仅在用户开启该设置时生效
chrome.downloads.onDeterminingFilename.addListener((item, suggest) => {
  if (!/\.(md|markdown|mdown|mkd)$/i.test(new URL(item.url).pathname)) return suggest();
  if (item.url.startsWith('file://') === false) return suggest();

  handleIntercept(item).then((ok) => { if (!ok) suggest(); });
  return true;
});

async function handleIntercept(item: chrome.downloads.DownloadItem) {
  const { fallbackViewer } = await chrome.storage.sync.get({ fallbackViewer: false });
  if (!fallbackViewer) return false;

  await chrome.downloads.cancel(item.id).catch(() => {});
  await chrome.downloads.erase({ id: item.id }).catch(() => {});

  const [tab] = await chrome.tabs.query({ active: true, lastFocusedWindow: true });
  const url = chrome.runtime.getURL('src/viewer/viewer.html') + '?src=' + encodeURIComponent(item.url);
  if (tab?.id) await chrome.tabs.update(tab.id, { url });
  else await chrome.tabs.create({ url });
  return true;
}
```

此路径需要一个独立的 `viewer.html`（因为原 tab 最终停在扩展页），但**渲染逻辑与 content script 完全复用** `render/markdown.ts`。代价：此路径下相对路径图片会失效，仍需 `assets.ts` 重写为 `file://` 绝对路径。

> **决策建议**：v1 先不做。等真的收到"打不开/变下载"的反馈再加。少一个 `downloads` 权限，商店审核顺畅得多。

### 4.5 render/markdown.ts —— 解析配置

```ts
// src/render/markdown.ts
import MarkdownIt from 'markdown-it';
import DOMPurify from 'dompurify';
import anchor from 'markdown-it-anchor';
import taskLists from 'markdown-it-task-lists';
import footnote from 'markdown-it-footnote';
import hljs from 'highlight.js';

const md = new MarkdownIt({
  html: true,          // 允许内联 HTML —— 必须配 DOMPurify，缺一不可
  linkify: true,
  typographer: false,
  breaks: false,
  highlight(str, lang) {
    if (lang && hljs.getLanguage(lang)) {
      try {
        return `<pre class="hljs"><code class="language-${lang}">${
          hljs.highlight(str, { language: lang }).value
        }</code></pre>`;
      } catch { /* 落到下面 */ }
    }
    return `<pre class="hljs"><code>${md.utils.escapeHtml(str)}</code></pre>`;
  },
})
  .use(anchor, {
    permalink: anchor.permalink.linkInsideHeader({ symbol: '#', placement: 'before' }),
    slugify: (s) => encodeURIComponent(String(s).trim().toLowerCase().replace(/\s+/g, '-')),
  })
  .use(taskLists, { enabled: true, label: true })
  .use(footnote);

/** 外链在新标签打开；内链（md 互链）保持原样，交给浏览器导航 */
const defaultLinkOpen =
  md.renderer.rules.link_open ??
  ((tokens, idx, options, _env, self) => self.renderToken(tokens, idx, options));

md.renderer.rules.link_open = (tokens, idx, options, env, self) => {
  const href = tokens[idx].attrGet('href') ?? '';
  if (/^https?:/i.test(href)) {
    tokens[idx].attrSet('target', '_blank');
    tokens[idx].attrSet('rel', 'noopener noreferrer');
  }
  return defaultLinkOpen(tokens, idx, options, env, self);
};

export function renderMarkdown(raw: string, baseUrl: string): string {
  const html = md.render(raw, { baseUrl });
  return DOMPurify.sanitize(html, {
    ADD_ATTR: ['target', 'rel', 'id', 'class', 'align', 'colspan', 'rowspan', 'checked', 'disabled', 'type'],
    FORBID_TAGS: ['script', 'style', 'iframe', 'object', 'embed', 'form', 'input', 'link', 'meta'],
    FORBID_ATTR: ['onerror', 'onload', 'onclick', 'onmouseover', 'srcdoc'],
    ALLOW_DATA_ATTR: false,
  });
}
```

**为什么必须 DOMPurify**：本地 md 也可能是从别处下载来的、被投毒的。开了 `html: true` 就等于允许任意 HTML 进入 `innerHTML`。虽然 `file://` 页面没有 CSP 兜底，但扩展注入的 content script 运行在 ISOLATED world，`<script>` 不会执行；真正的风险是 `<img onerror>` 这类需要在消毒层挡掉。

### 4.6 render/styles.ts —— CSS 内联注入

**不要**用 `<link href="chrome-extension://...">`：那需要 `web_accessible_resources`，还要处理 file:// 匹配，平添变量。

构建时把 CSS 当字符串导入，直接注入 `<style>`：

```ts
// src/render/styles.ts
import themeCss from './theme.css?inline';
import hljsCss from './hljs.css?inline';

const STYLE_ID = '__md_reader_styles__';

export function injectStyles(doc: Document) {
  if (doc.getElementById(STYLE_ID)) return;       // 幂等
  const style = doc.createElement('style');
  style.id = STYLE_ID;
  style.textContent = themeCss + '\n' + hljsCss;
  (doc.head ?? doc.documentElement).appendChild(style);
}
```

> `?inline` 是 Vite 的语法。若用其他打包器，等价操作是 `css-loader` 的 `exportType: 'string'` 或把 CSS 写成 TS 模板字符串。
> `file://` 页面没有 CSP，内联 `<style>` 不会被拦。

### 4.7 render/toc.ts —— 目录与滚动同步

```ts
// src/render/toc.ts
export function buildToc(root: HTMLElement) {
  const heads = root.querySelectorAll<HTMLElement>('h1, h2, h3, h4');
  if (heads.length < 3) return;   // 太短的文章不生成目录

  const nav = document.createElement('nav');
  nav.className = 'md-reader-toc';
  const ul = document.createElement('ul');

  heads.forEach((h) => {
    if (!h.id) h.id = 'h-' + Math.random().toString(36).slice(2, 8);
    const li = document.createElement('li');
    li.className = `toc-level-${h.tagName[1]}`;
    const a = document.createElement('a');
    a.href = '#' + h.id;
    a.textContent = h.textContent?.replace(/^#/, '').trim() ?? '';
    // 用原生锚点跳转：URL 不变，浏览器行为完全正常
    a.addEventListener('click', (e) => {
      e.preventDefault();
      h.scrollIntoView({ behavior: 'smooth', block: 'start' });
      history.replaceState(null, '', '#' + h.id);
    });
    li.appendChild(a);
    ul.appendChild(li);
  });

  nav.appendChild(ul);
  document.body.appendChild(nav);
  document.body.classList.add('md-reader-has-toc');
}

export function setupTocSync(root: HTMLElement) {
  const links = new Map<string, HTMLAnchorElement>();
  document.querySelectorAll<HTMLAnchorElement>('.md-reader-toc a').forEach((a) => {
    links.set(decodeURIComponent(a.hash.slice(1)), a);
  });
  if (!links.size) return;

  const io = new IntersectionObserver(
    (entries) => {
      const visible = entries
        .filter((e) => e.isIntersecting)
        .sort((a, b) => a.boundingClientRect.top - b.boundingClientRect.top)[0];
      if (!visible) return;
      links.forEach((a) => a.classList.remove('active'));
      links.get((visible.target as HTMLElement).id)?.classList.add('active');
    },
    { rootMargin: '-10% 0px -80% 0px' }
  );

  root.querySelectorAll('h1, h2, h3, h4').forEach((h) => io.observe(h));
}
```

## 五、库选型

| 用途 | 选型 | 理由 | 体积(min+gzip) |
|---|---|---|---|
| Markdown 解析 | **markdown-it** ✅ | CommonMark 兼容、插件生态最全、渲染规则可覆写 | ~35 KB |

| 代码高亮 | **highlight.js** ✅ | 开箱即用、语言覆盖全 | 按需 ~30 KB |
| | Shiki | 效果最好（VS Code 同款），体积大 | ~300 KB+ |

| 任务列表 | markdown-it-task-lists | GitHub 风格复选框 | ~2 KB |

## 七、风险清单

| 编号 | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | 用户未开启「允许访问文件网址」 | **功能完全不可用** | popup 首次打开即检测并展示图文引导；`chrome://extensions` 路径只做文本展示（扩展不能导航到 chrome://） |
| R2 | Chrome 内置文本查看器的 DOM 结构变化 | 取不到原文 | `readFromDom()` 三级退化（`body > pre` → `body.textContent`）+ SW fetch 兜底；**不依赖单一选择器** |
| R3 | 环境相关：某些机器上 `.md` 变下载 | 完全不渲染 | 可选 downloads 拦截层（4.4），默认关闭；收到反馈再启用 |
| R4 | 隐藏后渲染异常 → **白屏** | 体验灾难 | 严格 `try/finally` 恢复可见；读不到原文时直接 return，保持原样不动 |
| R5 | GBK/GB18030 编码的 md 显示乱码 | 中文用户高频痛点 | SW 路径用 `TextDecoder('gbk')` 自动回退（4.3） |
| R6 | 中文/空格/`#` 路径 | 打不开特定文件 | 本方案不构造 URL、不做 decode，直接把 `location.href` 交给 `fetch`，**从根上规避**（这曾是 v1 的重灾区） |
| R7 | 超大文件（>2 MB）渲染卡死 | 页面无响应 | 阈值降级为原始文本 + 顶部提示；极端情况放 Web Worker |
| R8 | Markdown 内嵌恶意 HTML | XSS | DOMPurify 强制消毒 + ISOLATED world 隔离 |
| R9 | 与其他 md 扩展同时注入 | DOM 互相覆盖 | `document.body.dataset.mdReaderDone` 做幂等标记；检测到 `__md_reader_styles__` 已存在则退出 |
| R10 | 用户按住 Ctrl+F5 想"另存" | 无处触发 | 与本方案无关（v2 不劫持下载） |
