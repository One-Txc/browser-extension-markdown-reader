# 表格操作条测试

每张表格左上方有一条操作条，四个按钮：

| 按钮 | 作用 | 再点一次 |
| --- | --- | --- |
| 三条左对齐横线 | 所有单元格内容左对齐 | 取消，回到文档自身的列对齐 |
| 三条居中横线 | 所有单元格内容居中 | 同上 |
| 三条右对齐横线 | 所有单元格内容右对齐 | 同上 |
| ⇄ 双向箭头 | 完全按内容展开（不折行，可横向滚动） | 恢复自动宽度 |

三个对齐按钮只改**单元格内容**的位置，表格本身始终靠左。默认不接管：
Markdown 里用 `:-:` 写好的列对齐会照常生效，三个按钮都不高亮。

## 自动宽度有三档

不用手动选，按列数自动决定：

| 档位 | 何时使用 | 列宽 | 溢出 |
| --- | --- | --- | --- |
| 折行 | 6 列及以内 | 浏览器按内容比例 | 内容折行，不出现滚动条 |
| 限幅展开 | 7 列及以上，且估算列宽总和超过正文宽度 | 逐列计算，长列最多约 12 个汉字 | 出现横向滚动条 |
| 完全展开 | 点最右边的 ⇄ 按钮 | 内容说了算 | 出现横向滚动条 |

限幅展开的两个条件缺一不可：列数够多、且真的放不下。七列全短的表仍然走折行，不会平白多出滚动条。
限幅的目的：宽表不再把短列压成两行，同时长说明列也不会撑成 800px 的单行。

## 2. 列宽不均：短列不应该折行

| 编号 | 名称 | 级别 | 说明与备注 |
| --- | --- | --- | --- |
| 1 | 解析器 | 高 | 负责把 Markdown 文本切成 token 流，再交给渲染器逐块输出；错误处理集中在入口处，不向下传播 |
| 2 | 渲染器 | 高 | 把 token 渲染成 HTML，并做 XSS 消毒 |
| 3 | 主题 | 中 | 只换 CSS 变量，不重建 DOM |
| 4 | 目录 | 低 | 依赖标题层级，滚动时用 IntersectionObserver 高亮 |

期望：「编号」「名称」「级别」的表头和内容都保持单行；「说明与备注」占大头、可以折行。

## 3. 文档自带列对齐：验证「默认跟随、点选覆盖、再点恢复」

| 默认左 | 默认中 | 默认右 |
| :--- | :---: | ---: |
| abc | abc | abc |
| 较长的文本 | 较长的文本 | 12345 |

刚打开时三列分别是左、中、右 —— 这是 Markdown 的 `:-:` 语法在起作用。
点任意一个对齐按钮，三列会全部变成那个方向；再点同一个按钮，回到左/中/右。

| 类型 | 内容 |

期望：这三格都能在宽度内折行，页面**不会**出现整页横向滚动条。

## 5. 长文本单元格：折行的代价

| 场景 | 说明 |
| --- | --- |
| 折行 | 单元格里的中文长句会折成多行，行高随内容增长。这是用行高换「不用横向滚动」的结果。 |
| 限幅展开 | 7 列以上且合计放不下时自动进入：长列最多约 12 个汉字，超出折行；整表横向可滚动。 |
| 完全展开 | 点最右边的 ⇄：列宽不再受限，长说明会一行铺开，代价是横向滚动距离变长。 |
